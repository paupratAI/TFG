\section{Experimental Report}
\label{sec:experimental_report}

This section collects the main experiments carried out during the project. It is
written as a self-contained summary, so the tested models are briefly described
before presenting the results. The common idea behind the prototype is to build
a hidden layer made of nonlinear tanh neurons, select useful neurons with a
Michigan-style evolutionary process, and then train a simple output layer on top
of the selected representation. Most experiments use a Ridge output layer with
GCV-based regularisation. One experiment replaces Ridge with a softmax output
trained with cross-entropy, and the final experiment returns to the original
motivation of the project: comparing the Michigan representation with a
Pittsburgh-style evolutionary representation.

\subsection{Experiment 1: Ridge/GCV Fitness Strategy Comparison}
\label{subsec:exp_strategy_comparison}

The first experiment compares the different strategies used to select hidden
neurons inside the Michigan-style population. This is important because, in
this architecture, one individual is only one neuron and not a complete neural
network. Therefore, the algorithm needs a criterion to decide which neurons are
useful enough to survive. The compared strategies are OMP, marginal $R^2$ with
diversity penalty, CFS, and CFS-AUC.

OMP selects neurons greedily according to how much they help to explain the
current residual, so it behaves like a sparse forward-selection method. The
marginal $R^2$ strategy gives high fitness to neurons that individually explain
the target well, while adding a diversity penalty to avoid keeping many neurons
that behave almost the same. CFS is a correlation-based criterion: it rewards
neurons that are correlated with the target and penalises redundancy between
neurons. CFS-AUC is the modified version introduced during the project; it uses
univariate AUC as the relevance term and Spearman correlation as the redundancy
term, which makes the criterion more directly related to binary classification.

The global results over Breast-W, Ionosphere, and Sonar are shown in
Table~\ref{tab:exp_strategy_overall}.

The best overall strategy is CFS. It obtains the highest validation accuracy,
test accuracy, and ROC-AUC, so it makes sense to use it as the main strategy in
the later Ridge experiments. The only weak point is the high MSE variance,
which means that Ridge scores can sometimes have unstable magnitudes even when
the final classification is correct. CFS-AUC is still interesting because it
uses AUC and Spearman-style redundancy, but in these experiments it is more
expensive and does not clearly beat CFS.

\subsection{Experiment 2: Ridge/GCV Against Standard Tabular Baselines}
\label{subsec:exp_ridge_baselines}

The second experiment checks whether the proposed ES-CFS Ridge/GCV model is
competitive when compared with standard tabular machine-learning methods. The
goal is not to claim that the prototype is always the best model, but to see
whether it is close to strong baselines such as RBF SVM, Random Forest, and
HistGradientBoosting.

In this comparison, ES-CFS Ridge/GCV is the main prototype: the hidden neurons
are selected by the evolutionary CFS strategy and the final output weights are
computed with Ridge regression, with the regularisation parameter selected by
GCV. RBF SVM is a kernel Support Vector Machine with a radial basis function
kernel, which is a strong nonlinear classifier for small tabular datasets.
Random Forest is an ensemble of decision trees trained on bootstrapped samples,
and HistGradientBoosting is a gradient-boosted tree model optimised for tabular
data. Logistic Regression is included as a simple linear probabilistic baseline.
Linear Ridge+GCV removes the hidden layer completely and applies Ridge directly
to the original features. Random tanh Ridge+GCV keeps the same Ridge output
layer but uses random nonlinear hidden neurons instead of evolved ones. Finally,
Gradient MLP is a conventional neural network trained by backpropagation, used
to compare the prototype against the more standard neural-network training
approach.

\subsection{Experiment 3: Ridge-Family Ablation}
\label{subsec:exp_ridge_ablation}

This experiment isolates the contribution of the evolved hidden representation.
For that, three Ridge variants are compared: Ridge directly on the input
features, Ridge on random tanh features, and Ridge on the evolved ES-CFS hidden
features. This is useful because it tells us whether the evolutionary layer is
actually adding value. Linear Ridge+GCV is the simplest version, because the
model only learns a regularised linear combination of the original variables.
Random tanh Ridge+GCV adds nonlinear neurons, but their parameters are not
optimised, so it tests whether nonlinearity alone is enough. ES-CFS Ridge+GCV
uses the same number of hidden neurons as the random version, but they have been
selected by the evolutionary fitness function, so any improvement can be
attributed to the learned representation rather than only to the Ridge solver.

from adding nonlinear features, but from selecting useful nonlinear features.

\subsection{Experiment 4: GCV Regularisation Diagnostic}
\label{subsec:exp_gcv_diagnostic}

The fourth experiment studies the behaviour of GCV when choosing the Ridge
regularisation parameter. This is relevant because one of the strengths of the
Ridge architecture is that the output layer can be solved analytically and
$\lambda_R$ can be selected without using the test set. In this experiment the
hidden layer is kept fixed after ES-CFS selection, and only the output-layer
regularisation is changed. This separates the effect of the analytical Ridge
solver from the effect of the evolutionary neuron selection.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\textwidth]{runs/ridge_defense/lambda_sensitivity.png}
\caption{Sensitivity of the Ridge output layer to fixed $\lambda_R$ values compared with the GCV-selected value.}
\label{fig:exp_lambda_sensitivity}
\end{figure}

The diagnostic shows that GCV selects a stable regularisation region. The point
is not that GCV always chooses the best possible test value, because using test
performance to choose $\lambda_R$ would be invalid. What matters is that GCV
provides an automatic and principled way to select the regularisation parameter
once the hidden activations are fixed. This supports the analytical character
of the Ridge/GCV architecture.

\subsection{Experiment 5: Accuracy--Time Trade-Off}
\label{subsec:exp_accuracy_time}

This experiment looks at the computational cost of the prototype. The Ridge
output solve is fast once the hidden activations are known, but the
evolutionary search for useful neurons is more expensive. The goal is to see
where the prototype is placed when both accuracy and fitting time are taken
into account. For the prototype, fitting time includes the hidden-neuron search
and the final Ridge/GCV output solve. For the external baselines, it corresponds
to the standard training time of each scikit-learn model on the same data split.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\textwidth]{runs/ridge_defense/accuracy_time_tradeoff.png}
\caption{Accuracy and fitting-time trade-off between the Ridge prototype and standard baselines.}
\label{fig:exp_accuracy_time}
\end{figure}

The prototype is not the fastest model in the comparison. This is expected,
because the evolutionary hidden-layer search dominates the runtime. However,
its accuracy is close to strong tabular baselines. Therefore, the value of the
prototype is not that it is the cheapest classifier, but that it combines
evolutionary representation learning with an analytical Ridge/GCV output
layer.

\subsection{Experiment 6: Regression-Oriented Ridge Benchmark}
\label{subsec:exp_regression}

The sixth experiment tests whether the Ridge/GCV architecture also has value in
regression. This is a natural question because the Ridge output layer is
originally a least-squares regressor. The experiment uses Higgs as a numeric
$0/1$ score-regression task, and Friedman1 and Diabetes as continuous
regression datasets.

The compared models follow the same logic as in the classification ablation.
Linear Ridge+GCV predicts the target directly from the original input features.
Random tanh Ridge+GCV first maps the input through randomly generated tanh
neurons and then fits Ridge on those random features. ES-selected Ridge+GCV uses
the Michigan evolutionary stage to choose the nonlinear hidden neurons before
the Ridge output layer is fitted. HistGradientBoosting is a tree-based
boosting model that is usually very strong on tabular regression problems, and
Gradient MLP is a standard neural network trained with gradient descent. This
experiment therefore checks both whether the prototype improves over simpler
Ridge variants and whether it is competitive with common nonlinear regressors.

\subsection{Experiment 7: Validation-Based Regression Strategy Selection}
\label{subsec:exp_regression_strategy_selection}

This experiment looks more closely at the regression benchmark and asks whether
the same neuron-selection strategy works best for every regression dataset.
This matters because the Michigan-style architecture depends heavily on
credit-assignment, and different problems may require different selection
criteria. ES-CFS, ES-OMP, and ES-$R^2$ all use the same final Ridge/GCV output
layer; what changes is only the fitness rule used to decide which hidden
neurons are kept. This makes the comparison useful because it isolates the
selection criterion from the output model.

\subsection{Experiment 8: Lasso Output-Layer Filtering}
\label{subsec:exp_lasso}

The eighth experiment studies whether Lasso can be used as a second filtering
stage after the Michigan selection step. The ES already selects 50 neurons from
a larger pool of 400 candidates. Lasso can then remove some of these surviving
neurons by setting their output coefficients to zero.

Three output-layer variants are compared. Full ES-CFS Ridge+GCV is the original
model, where all 50 selected neurons remain active and the output layer is a
Ridge model. ES-CFS Lasso replaces the Ridge output with a Lasso output, so the
same selected hidden layer is used but some output weights can become exactly
zero. Lasso-screened ES-CFS Ridge+GCV uses Lasso only as a filter: first it
identifies the active neurons, and then Ridge+GCV is fitted again using only
those remaining neurons. This last version is interesting because it tries to
combine Lasso sparsity with the stability of the Ridge output layer.

This experiment gives a strong sparsity result. Full Ridge+GCV has the best

makes Lasso useful as a compression and interpretability mechanism, even if it
does not completely replace Ridge.

\subsection{Experiment 10: Multiclass Softmax Benchmark}
\label{subsec:exp_softmax}

The tenth experiment studies the probabilistic version of the architecture.
Ridge classification produces scores, but not probabilities. The softmax
architecture solves this for multiclass classification by producing one logit
per class and converting the logits into class probabilities.

Linear Softmax CE is a multinomial logistic-regression model trained with
cross-entropy directly on the original features. Random tanh Softmax CE uses a
random nonlinear hidden layer before the softmax output, while ES-CFS Softmax CE
uses the evolved hidden representation from the prototype and then trains the
softmax layer with cross-entropy. HistGradientBoosting and Gradient MLP are
included again as strong tabular and neural baselines. Besides accuracy and
macro-F1, the experiment reports cross-entropy and ECE. Cross-entropy evaluates
the quality of the predicted probabilities, and ECE measures calibration, that
is, whether predicted confidence matches empirical correctness.

\subsection{Experiment 11: Michigan vs. Pittsburgh Representation}
\label{subsec:exp_michigan_pittsburgh}

The last experiment is the most directly connected to the original motivation
of the project. The initial question was whether a neural architecture based on
the Michigan idea could be useful in a one-hidden-layer neural network. In a
Michigan representation, each individual is only one hidden neuron. The final
hidden layer is therefore not encoded by a single chromosome, but by the
surviving population of neurons. In a Pittsburgh representation, each
individual encodes a complete solution. In this case, one individual is a full
hidden layer with all its neurons.

The comparison was redesigned from scratch to make the difference between both
approaches as isolated as possible. Both architectures use the same datasets,
the same train/validation/test split, the same preprocessing, the same number
of hidden neurons in the final model, the same tanh activation function, and
the same analytic Ridge+GCV output layer. The final checkpoint is also selected
in the same way: the model with the best validation accuracy is kept, using
validation MSE as a tie-breaker. This means that the comparison is not between
different output solvers or different data pipelines, but between two ways of
representing and searching the hidden layer.

Three variants are compared. Michigan ES-CFS is the proposed prototype. It
keeps a population of 50 neurons, creates 250 new candidate neurons per
generation, selects the next hidden layer with the CFS credit-assignment
criterion, and solves the Ridge+GCV output once per generation. Pittsburgh ES
matched budget is the fairest Pittsburgh comparison in terms of newly generated
hidden units. It has 5 parent networks and creates 5 offspring networks per
generation. Since each network contains 50 hidden neurons, this also creates
250 new hidden neurons per generation. However, because Pittsburgh evaluates
whole networks, it must solve Ridge+GCV for 10 complete hidden layers every
generation. Pittsburgh ES larger population gives the Pittsburgh representation
a stronger search budget: it uses 12 parents and 12 offspring networks, so it
creates 600 new hidden neurons and solves Ridge+GCV 24 times per generation.
This second Pittsburgh variant is included to check whether a larger
whole-network population can recover the performance lost under the matched
budget setting.

The experiment was run on Breast-W, Ionosphere, and Sonar with five seeds
($42$--$46$), 50 generations, and 50 hidden neurons in the final architecture.
The reproducible implementation is in \texttt{benchmark\_level1.py}, and the
generated plots and JSON summary are stored in
\texttt{runs/michigan\_pittsburgh/}.

The results in Table~\ref{tab:exp_michigan_pittsburgh_overall} use mean
$\pm$ standard error over the 15 dataset/seed runs.

The per-dataset results make the interpretation clearer. On Breast-W, all

test accuracy. This dataset is relatively easy for the tested models, so a
complete-network search can perform very well. The difference appears on the
harder datasets. On Ionosphere, Michigan reaches $0.9268$ test accuracy, while

Michigan reaches $0.8190$, while the matched Pittsburgh variant falls to
$0.7429$ and the larger Pittsburgh variant reaches $0.7905$. This supports the
idea that searching with neuron-level individuals can be more robust when the
number of samples is limited and a full hidden layer is a large object to
optimise at once.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\textwidth]{runs/michigan_pittsburgh/michigan_pittsburgh_cost.png}
\caption{Computational cost of the Michigan and Pittsburgh representations.}
\label{fig:exp_michigan_pittsburgh_cost}

The computational-cost plot shows why this result gives value to the
prototype. The matched Pittsburgh variant creates the same number of new hidden
neurons per generation as Michigan: 250. Even so, it is almost three times
slower on average, because it evaluates 10 complete hidden layers and therefore
solves Ridge+GCV 10 times per generation. Michigan solves Ridge+GCV only once
per generation, after selecting the neuron population. The larger Pittsburgh
variant is around 6.7 times slower than Michigan and solves Ridge+GCV 24 times
per generation. Therefore, increasing the Pittsburgh search budget improves its
test accuracy only slightly, but it increases cost substantially.

\label{fig:exp_michigan_pittsburgh_convergence}
\end{figure}

The accuracy-time plot summarises the trade-off. Michigan is placed in the best
region of the plot: higher test accuracy and lower training time. Pittsburgh
does improve validation accuracy during evolution, as shown in the convergence
plot, but this does not translate into better test performance. This is a very
important conclusion for the thesis. It suggests that the Michigan
representation is not only a different way to encode a neural network; in this
prototype, it also changes the computational structure of the training problem.
Instead of evaluating many full networks, the algorithm searches locally for
useful hidden neurons and uses Ridge+GCV only after the hidden population has
been selected.

This experiment does not prove that Michigan representations are always better
than Pittsburgh representations. The tested datasets are small binary tabular
datasets, and a different Pittsburgh implementation with more advanced genetic
operators could behave differently. However, under a controlled setting where
activation function, hidden width, output solver, validation selection, and data
splits are shared, the Michigan version obtains a better accuracy-time trade-off
and a smaller generalisation gap. This directly supports the original
hypothesis of the project: combining a Michigan-style evolutionary search with
a one-hidden-layer neural network and an analytic Ridge/GCV output layer can
give real practical value compared with evolving complete hidden layers.

%\subsection{Overall Experimental Interpretation}
%\label{subsec:exp_overall_interpretation}

%Taken together, the experiments show that the prototype has a clear value, but also clear limits. The Ridge/GCV architecture is competitive with strong tabular baselines and, more importantly, the ablations show that the evolved hidden representation is doing useful work. The regression experiments show that the same idea can also improve continuous prediction, although it does not beat every specialised regressor. The Lasso experiments add a useful sparsification mechanism, reducing the final hidden layer by more than half while keeping almost the same test accuracy. The softmax benchmark shows that the same hidden representation can be used in a probabilistic multiclass setting, at the cost of losing the closed-form Ridge/GCV output solve. Finally, the Michigan--Pittsburgh benchmark supports the original motivation of the project: neuron-level evolution can obtain a better accuracy-time trade-off than complete-layer evolution under the same Ridge/GCV output architecture.
